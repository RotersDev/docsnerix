A **API Pix da Nerix** permite **receber** (criar cobranças Pix) e **enviar** (sacar pra uma chave Pix normal ou pagar um Pix copia e cola) usando a mesma API Key, de forma simples e direta.

<Info>
  Pagamentos recebidos aprovados caem automaticamente na carteira unificada do dono da API Key e aparecem com origem `API`. Pagamentos enviados debitam o saldo dessa mesma carteira.
</Info>

## Base URL

```txt
https://api.nerix.com.br/api/v1
```

## Autenticação

Envie sua API Key no header `Authorization`:

```http
Authorization: Bearer SUA_API_KEY
```

Também são aceitos:

```http
x-nerix-api-key: SUA_API_KEY
x-nerix-builder-key: SUA_API_KEY
x-builder-api-key: SUA_API_KEY
```

# Receber Pix (cobrança)

## Criar Pix

```http
POST /pix/transactions
```

### Body

<ParamField body="amount" type="number" required>
  Valor em centavos. Exemplo: `1490` representa R\$ 14,90.
</ParamField>

### Exemplo

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/transactions" \
  --header "Authorization: Bearer SUA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "amount": 1490
  }'
```

```js
const res = await fetch("https://api.nerix.com.br/api/v1/pix/transactions", {
  method: "POST",
  headers: {
    Authorization: "Bearer SUA_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 1490,
  }),
});

const pix = await res.json();
```

### Resposta

```json
{
  "id": "pix_6f4d9b8c2a1e4f7a9b0c1d2e",
  "status": "pending",
  "amount": 1490,
  "fee": 120,
  "netAmount": 1370,
  "copyPaste": "00020126580014br.gov.bcb.pix...",
  "qrCodeBase64": "data:image/png;base64,iVBORw0KGgoAAA...",
  "expiresAt": "2026-07-28T23:59:59.000Z",
  "provider": "woovi",
  "paymentId": "id_do_provedor",
  "payer": null,
  "paidAt": null,
  "createdAt": "2026-07-28T18:10:00.000Z",
  "updatedAt": "2026-07-28T18:10:00.000Z"
}
```

Quando o pagamento é confirmado, `payer` passa a vir preenchido com a identidade de quem pagou, conferida pelo próprio banco (via o provedor Pix) — não é o que foi digitado em nenhum formulário:

```json
"payer": { "name": "João Silva", "document": "12345678900" }
```

## Campos importantes

| Campo | Descrição |
| --- | --- |
| `id` | ID da cobrança na Nerix. Salve este valor para consultar depois. |
| `status` | Status atual da cobrança. |
| `amount` | Valor bruto em centavos. |
| `fee` | Taxa em centavos. |
| `netAmount` | Valor líquido em centavos. |
| `copyPaste` | Código Pix copia e cola. |
| `qrCodeBase64` | Imagem do QR Code em Base64, quando disponível. |
| `provider` | Qual provedor Pix processou essa cobrança (o que estiver ativo na carteira no momento). |
| `paymentId` | ID interno do pagamento/provedor para conciliação. |
| `payer` | `{ name, document }` de quem pagou, confirmado pelo provedor. `null` até o pagamento ser aprovado (e sempre `null` quando o provedor ativo não expõe esse dado). |

<Note>
  `payer` depende do provedor Pix ativo na carteira no momento da cobrança (escolhido nas configurações da carteira). A maioria devolve nome e documento; um deles hoje só devolve o nome, sem documento.
</Note>

## Consultar Pix

```http
GET /pix/transactions/{id}
```

```bash
curl --request GET \
  --url "https://api.nerix.com.br/api/v1/pix/transactions/pix_6f4d9b8c2a1e4f7a9b0c1d2e" \
  --header "Authorization: Bearer SUA_API_KEY"
```

## Verificar pagamento

```http
POST /pix/transactions/{id}/check
```

Use este endpoint para consultar o provedor Pix e atualizar o status salvo na Nerix.

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/transactions/pix_6f4d9b8c2a1e4f7a9b0c1d2e/check" \
  --header "Authorization: Bearer SUA_API_KEY"
```

Quando o pagamento for confirmado:

- `status` muda para `paid`.
- `paidAt` é preenchido.
- `payer` é preenchido, se o provedor expuser esse dado.
- O valor líquido entra na carteira unificada.
- A movimentação aparece como origem `API`.

## Status

| Status | Descrição |
| --- | --- |
| `pending` | Aguardando pagamento. |
| `paid` | Pago. |
| `failed` | Falhou. |
| `cancelled` | Cancelado. |
| `refunded` | Reembolsado. |

## Erros comuns

### API Key inválida

```json
{
  "error": "API key inválida ou inativa"
}
```

### Valor inválido

```json
{
  "error": "Valor inválido. Envie amount em centavos."
}
```

### Provedor Pix indisponível

```json
{
  "error": "Nenhum provedor Pix ativo na carteira."
}
```

### Cobrança não encontrada

```json
{
  "error": "Cobrança Pix não encontrada."
}
```

# Enviar Pix (sacar / pagar)

Envia dinheiro da carteira unificada pra um destino Pix. Um único endpoint, dois jeitos de informar o destino:

- **Chave Pix normal** — CPF, CNPJ, e-mail, telefone ou chave aleatória. Você informa o valor.
- **Pix copia e cola** — código de **valor fixo** de terceiro. O valor vem do próprio código; não envie `amount` nesse caso.

Informe **exatamente um dos dois** (`pix_key` ou `qr_code`) por chamada — nunca os dois juntos.

<Warning>
  Essa operação move dinheiro para fora da carteira. O mesmo saque nunca é processado duas vezes (proteção por idempotência quando é copia e cola), e há um limite de operações de saída por hora — o mesmo aplicado aos saques feitos pelo painel, configurável por conta.
</Warning>

## Enviar Pix

```http
POST /pix/payouts
```

### Body

<ParamField body="pix_key" type="string">
  Chave Pix de destino: CPF, CNPJ, e-mail, telefone ou chave aleatória. Use junto com `amount`. Não envie junto com `qr_code`.
</ParamField>

<ParamField body="pix_key_type" type="string">
  `CPF`, `CNPJ`, `EMAIL`, `PHONE` ou `RANDOM`. Opcional — se omitido, o tipo é inferido pelo formato da chave.
</ParamField>

<ParamField body="amount" type="number">
  Valor em centavos. Obrigatório quando usa `pix_key`. Ignorado quando usa `qr_code` (o valor vem do próprio código).
</ParamField>

<ParamField body="qr_code" type="string">
  Código Pix copia e cola de **valor fixo** a pagar. Não envie junto com `pix_key`. Códigos dinâmicos sem valor definido são rejeitados.
</ParamField>

### Exemplo — chave Pix normal

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/payouts" \
  --header "Authorization: Bearer SUA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "pix_key": "cliente@exemplo.com",
    "pix_key_type": "EMAIL",
    "amount": 1490
  }'
```

```js
const res = await fetch("https://api.nerix.com.br/api/v1/pix/payouts", {
  method: "POST",
  headers: {
    Authorization: "Bearer SUA_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    pix_key: "cliente@exemplo.com",
    pix_key_type: "EMAIL",
    amount: 1490,
  }),
});

const payout = await res.json();
```

### Exemplo — Pix copia e cola

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/payouts" \
  --header "Authorization: Bearer SUA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "qr_code": "00020126580014br.gov.bcb.pix..."
  }'
```

```js
const res = await fetch("https://api.nerix.com.br/api/v1/pix/payouts", {
  method: "POST",
  headers: {
    Authorization: "Bearer SUA_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    qr_code: "00020126580014br.gov.bcb.pix...",
  }),
});

const payout = await res.json();
```

### Resposta

```json
{
  "id": "payout_1234",
  "status": "paid",
  "amount": 1490,
  "fee": 120,
  "totalDebited": 1610,
  "pixKey": "cliente@exemplo.com",
  "merchantName": null,
  "recipient": { "name": "João Macaco", "document": "12345678900" },
  "provider": "woovi",
  "paidAt": "2026-08-23T18:10:00.000Z",
  "createdAt": "2026-08-23T18:10:00.000Z",
  "updatedAt": "2026-08-23T18:10:00.000Z"
}
```

## Campos importantes

| Campo | Descrição |
| --- | --- |
| `id` | ID do pagamento na Nerix. Salve pra consultar depois. |
| `status` | `processing`, `paid` ou `failed` — veja a tabela de status abaixo. |
| `amount` | Valor enviado, em centavos. |
| `fee` | Taxa cobrada pela Nerix, em centavos. |
| `totalDebited` | Total debitado da carteira (`amount` + `fee`), em centavos. |
| `pixKey` | Chave Pix de destino usada nesse envio. |
| `merchantName` | Nome identificado dentro do código Pix copia e cola, quando esse foi o modo usado. `null` em envio por chave. |
| `recipient` | `{ name, document }` de quem **recebeu de fato**, confirmado pelo provedor — não é a chave que você enviou. `null` até confirmar. |
| `provider` | Qual provedor processou esse envio (o que estiver ativo na carteira no momento). |
| `paidAt` | Data de confirmação do envio. `null` enquanto `status` é `processing`. |

<Note>
  O provedor que processa o envio é configurável na carteira (Woovi ou Promisse). Um deles confirma na hora (a resposta já vem `paid` ou `failed`); o outro processa em fila e confirma pouco depois — nesse caso a resposta vem `processing` e você consulta o resultado com `GET /pix/payouts/{id}`.
</Note>

## Consultar envio

```http
GET /pix/payouts/{id}
```

Funciona tanto pra envio por chave Pix quanto por copia e cola.

```bash
curl --request GET \
  --url "https://api.nerix.com.br/api/v1/pix/payouts/payout_1234" \
  --header "Authorization: Bearer SUA_API_KEY"
```

## Status

| Status | Descrição |
| --- | --- |
| `processing` | Enviado ao provedor, aguardando confirmação. O valor já saiu da carteira. |
| `paid` | Confirmado — o dinheiro chegou ao destinatário. |
| `failed` | Falhou. O valor debitado é estornado automaticamente para a carteira. |

```json
}
```

```json
{
  "error": "Informe apenas um dos dois: \"pix_key\" ou \"qr_code\".",

```

```json
{
  "error": "Informe \"amount\" em centavos.",
```

## Boas práticas

- Envie valores sempre em centavos.
- Salve o `id` retornado pela Nerix para cada cobrança ou envio.
- Não exponha sua API Key no frontend público.
- Ao **receber**: use `GET` para consultar o status salvo e `POST /check` só quando quiser forçar a verificação no provedor. Evite consultar em loop agressivo.
- Ao **enviar**: trate `PIX_PAYMENT_DUPLICATE` como sucesso idempotente (o Pix já foi processado) em vez de erro. Se a resposta vier `processing`, faça `GET /pix/payouts/{id}` periodicamente até virar `paid` ou `failed` — não assuma sucesso antes disso.
