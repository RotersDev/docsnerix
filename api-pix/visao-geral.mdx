A **API Pix da Nerix** permite **receber** (criar cobranças Pix) e **enviar** (pagar um Pix copia e cola) usando a mesma API Key, de forma simples e direta.

<Info>
  Pagamentos recebidos aprovados caem automaticamente na carteira unificada do dono da API Key e aparecem com origem `API`. Pagamentos enviados debitam o saldo dessa mesma carteira.
</Info>

## Base URL

```txt
https://api.nerix.com.br/api/v1
```

## Autenticação

Envie sua API Key no header `Authorization`:

```http
Authorization: Bearer SUA_API_KEY
```

Também são aceitos:

```http
x-nerix-api-key: SUA_API_KEY
x-nerix-builder-key: SUA_API_KEY
x-builder-api-key: SUA_API_KEY
```

# Receber Pix (cobrança)

## Criar Pix

```http
POST /pix/transactions
```

### Body

<ParamField body="amount" type="number" required>
  Valor em centavos. Exemplo: `1490` representa R\$ 14,90.
</ParamField>

### Exemplo

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/transactions" \
  --header "Authorization: Bearer SUA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "amount": 1490
  }'
```

```js
const res = await fetch("https://api.nerix.com.br/api/v1/pix/transactions", {
  method: "POST",
  headers: {
    Authorization: "Bearer SUA_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 1490,
  }),
});

const pix = await res.json();
```

### Resposta

```json
{
  "id": "pix_6f4d9b8c2a1e4f7a9b0c1d2e",
  "status": "pending",
  "amount": 1490,
  "fee": 120,
  "netAmount": 1370,
  "copyPaste": "00020126580014br.gov.bcb.pix...",
  "qrCodeBase64": "data:image/png;base64,iVBORw0KGgoAAA...",
  "expiresAt": "2026-07-28T23:59:59.000Z",
  "provider": "woovi",
  "paymentId": "id_do_provedor",
  "paidAt": null,
  "createdAt": "2026-07-28T18:10:00.000Z",
  "updatedAt": "2026-07-28T18:10:00.000Z"
}
```

## Campos importantes

| Campo | Descrição |
| --- | --- |
| `id` | ID da cobrança na Nerix. Salve este valor para consultar depois. |
| `status` | Status atual da cobrança. |
| `amount` | Valor bruto em centavos. |
| `fee` | Taxa em centavos. |
| `netAmount` | Valor líquido em centavos. |
| `copyPaste` | Código Pix copia e cola. |
| `qrCodeBase64` | Imagem do QR Code em Base64, quando disponível. |
| `paymentId` | ID interno do pagamento/provedor para conciliação. |

## Consultar Pix

```http
GET /pix/transactions/{id}
```

```bash
curl --request GET \
  --url "https://api.nerix.com.br/api/v1/pix/transactions/pix_6f4d9b8c2a1e4f7a9b0c1d2e" \
  --header "Authorization: Bearer SUA_API_KEY"
```

## Verificar pagamento

```http
POST /pix/transactions/{id}/check
```

Use este endpoint para consultar o provedor Pix e atualizar o status salvo na Nerix.

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/transactions/pix_6f4d9b8c2a1e4f7a9b0c1d2e/check" \
  --header "Authorization: Bearer SUA_API_KEY"
```

Quando o pagamento for confirmado:

- `status` muda para `paid`.
- `paidAt` é preenchido.
- O valor líquido entra na carteira unificada.
- A movimentação aparece como origem `API`.

## Status

| Status | Descrição |
| --- | --- |
| `pending` | Aguardando pagamento. |
| `paid` | Pago. |
| `failed` | Falhou. |
| `cancelled` | Cancelado. |
| `refunded` | Reembolsado. |

## Erros comuns

### API Key inválida

```json
{
  "error": "API key inválida ou inativa"
}
```

### Valor inválido

```json
{
  "error": "Valor inválido. Envie amount em centavos."
}
```

### Provedor Pix indisponível

```json
{
  "error": "Nenhum provedor Pix ativo na carteira."
}
```

### Cobrança não encontrada

```json
{
  "error": "Cobrança Pix não encontrada."
}
```

# Enviar Pix (pagar / sacar)

Paga um código Pix copia e cola **de valor fixo** debitando o saldo disponível da sua carteira unificada. É uma chamada única: valida, debita e envia — não existe um passo separado de "decodificar antes de confirmar".

<Warning>
  Essa operação move dinheiro para fora da carteira. O mesmo código Pix nunca é processado duas vezes (proteção por idempotência), e há um limite de operações de saída por hora, o mesmo aplicado aos saques feitos pelo painel.
</Warning>

## Pagar Pix

```http
POST /pix/payouts
```

### Body

<ParamField body="qr_code" type="string" required>
  Código Pix copia e cola a ser pago. Precisa ser um Pix de **valor fixo** — códigos dinâmicos sem valor definido são rejeitados.
</ParamField>

### Exemplo

```bash
curl --request POST \
  --url "https://api.nerix.com.br/api/v1/pix/payouts" \
  --header "Authorization: Bearer SUA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "qr_code": "00020126580014br.gov.bcb.pix..."
  }'
```

```js
const res = await fetch("https://api.nerix.com.br/api/v1/pix/payouts", {
  method: "POST",
  headers: {
    Authorization: "Bearer SUA_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    qr_code: "00020126580014br.gov.bcb.pix...",
  }),
});

const payout = await res.json();
```

### Resposta

```json
{
  "id": "payout_1234",
  "status": "paid",
  "amount": 1490,
  "fee": 120,
  "totalDebited": 1610,
  "merchantName": "Loja Exemplo",
  "paidAt": "2026-08-23T18:10:00.000Z",
  "createdAt": "2026-08-23T18:10:00.000Z",
  "updatedAt": "2026-08-23T18:10:00.000Z"
}
```

## Campos importantes

| Campo | Descrição |
| --- | --- |
| `id` | ID do pagamento na Nerix. |
| `status` | Status final do pagamento (`paid` ou `failed`). |
| `amount` | Valor do Pix pago, em centavos. |
| `fee` | Taxa cobrada pela Nerix, em centavos. |
| `totalDebited` | Total debitado da carteira (`amount` \+ `fee`), em centavos. |
| `merchantName` | Nome do recebedor identificado no código Pix, quando disponível. |
| `paidAt` | Data de confirmação do envio. |

<Note>
  Esse endpoint é síncrono: a resposta já vem com o status final (`paid` ou `failed`). Não existe estado `pending` para pagamentos enviados.
</Note>

## Status

| Status | Descrição |
| --- | --- |
| `paid` | Pix enviado e confirmado. |
| `failed` | Falha ao enviar — o valor debitado é estornado automaticamente para a carteira. |

## Erros comuns

### Código Pix ausente ou inválido

```json
{
  "error": "Informe o codigo Pix copia e cola.",
  "code": "PIX_PAYMENT_MISSING_CODE"
}
```

```json
{
  "error": "Código Pix inválido",
  "code": "PIX_PAYMENT_INVALID_CODE"
}
```

### Código Pix sem valor fixo

```json
{
  "error": "Não conseguimos identificar o valor dessa cobrança Pix. Confira se o código está completo.",
  "code": "PIX_PAYMENT_NO_FIXED_AMOUNT"
}
```

### Código já pago (idempotência)

```json
{
  "error": "Esse código Pix já foi pago ou está sendo processado.",
  "code": "PIX_PAYMENT_DUPLICATE"
}
```

### Saldo insuficiente

```json
{
  "error": "Saldo insuficiente. Você precisa de R$ 16,10 (...) e tem R$ 10,00 disponível.",
  "code": "PIX_PAYMENT_INSUFFICIENT_BALANCE"
}
```

### Limite de operações por hora

```json
{
  "error": "Você já movimentou a carteira recentemente. Aguarde 1 hora para tentar de novo.",
  "code": "PIX_PAYMENT_RATE_LIMIT"
}
```

### Conta não verificada

```json
{
  "error": "Verifique sua conta para solicitar saques.",
  "code": "ACCOUNT_KYC_NOT_APPROVED"
}
```

### Valor acima do limite permitido

```json
{
  "error": "O valor máximo permitido é R$ 5.000,00 (incluindo a taxa).",
  "code": "PIX_PAYMENT_MAX_AMOUNT"
}
```

## Boas práticas

- Envie valores sempre em centavos.
- Salve o `id` retornado pela Nerix para cada cobrança ou pagamento.
- Não exponha sua API Key no frontend público.
- Ao **receber**: use `GET` para consultar o status salvo e `POST /check` só quando quiser forçar a verificação no provedor. Evite consultar em loop agressivo.
- Ao **enviar**: trate `PIX_PAYMENT_DUPLICATE` como sucesso idempotente (o Pix já foi processado) em vez de erro — é a proteção contra reenvio.
